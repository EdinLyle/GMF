# GMF (Genetic Mutation Framework) v2.0 功能拓展开发任务

## 项目背景
GMF是一个基于Electron的轻量级AI安全测试桌面应用，专注于提示词安全评估与红队测试。当前版本需要拓展核心功能模块，实现本地化的智能安全测试能力。

## 现有技术栈
- **核心框架**: Electron 28.1.0 + React 18.2.0 + TypeScript 5.3.3 + Vite 5.0.10
- **UI组件**: Radix UI 1.x + Tailwind CSS 3.4.0 + Framer Motion 10.18.0 + Lucide React 0.303.0
- **状态管理**: Zustand 4.4.7
- **数据库**: SQLite (sql.js 1.12.0)
- **构建工具**: Electron Builder 24.9.1

## 拓展功能目标
实现三大核心模块：智能本地变体引擎、本地多模型对比测试矩阵、离线语义分析引擎。

## 模块一：智能本地变体引擎 (Genetic Variation Engine)

### 功能定义
基于遗传算法的本地化提示词变异生成系统，通过模拟自然选择过程自动生成高风险的提示词变体，无需依赖外部API服务。

### 基本规则

#### 1.1 核心算法架构规则
- **纯本地实现**: 所有遗传算法逻辑必须在Electron主进程中通过TypeScript实现，禁止依赖外部计算服务
- **种群管理**: 种群规模可配置（默认50-200个个体），支持动态调整
- **代数控制**: 支持设置最大进化代数（默认20-100代），允许中途暂停/继续/回退
- **精英保留**: 每代保留Top 10%最优个体直接进入下一代，防止优秀基因丢失
- **多样性维护**: 必须实现种群多样性监测，当多样性低于阈值时自动触发变异增强

#### 1.2 变异算子规则
- **中文优化**: 针对中文语境设计专用变异算子，包括但不限于：
  - 同义词替换（使用本地同义词库）
  - 句式结构重组（主动/被动转换、语序调整）
  - 编码混淆（Unicode转义、相似字符替换）
  - 语义分割与重组（长句拆分、逻辑重组）
  - 情感极性注入（添加紧急、恳求、权威等情感标签）
- **变异概率**: 交叉概率0.7-0.9，变异概率0.1-0.3，支持用户自定义
- **自适应变异**: 当种群收敛停滞时，自动提高变异概率至0.5

#### 1.3 适应度评估规则
- **本地评估**: 支持三种评估模式：
  - 启发式规则评分（关键词匹配、结构分析，零依赖）
  - 本地模型评估（Ollama/LM Studio等本地API）
  - 历史数据相似度匹配（基于SQLite存储的历史攻击案例）
- **多目标优化**: 同时优化三个维度：
  - 攻击成功率（0-1权重可配置）
  - 语义保持度（与原意相似度，防止过度变异）
  - 隐蔽性评分（绕过常见过滤器的概率）
- **实时反馈**: 每完成一代评估，必须向渲染进程推送进度数据

#### 1.4 数据持久化规则
- **进化历史存储**: 使用SQLite存储完整进化历史，包括每代种群状态、适应度分布、最佳个体
- **断点续传**: 支持从任意代数恢复进化过程
- **导出功能**: 支持导出进化动画数据（JSON格式）和静态报告（PDF/HTML）

#### 1.5 UI交互规则
- **实时可视化**: 使用Recharts展示适应度曲线（最佳/平均/最差适应度变化）
- **种群多样性热力图**: 展示个体间相似度矩阵
- **个体预览**: 点击任意代数可查看该代最佳个体的完整提示词及评分详情
- **时间轴控制**: 提供播放/暂停/快进/回退按钮，支持拖拽到指定代数
- **对比视图**: 支持并排展示不同进化路径的结果对比

## 模块二：本地多模型对比测试矩阵 (Local Model Comparison Matrix)

### 功能定义
自动发现本地部署的AI模型（Ollama、LM Studio、llama.cpp等），对同一组提示词进行并行安全测试，生成可视化对比报告。

### 基本规则

#### 2.1 模型发现与管理规则
- **自动扫描**: 启动时自动扫描本地常见模型服务端口：
  - Ollama默认端口11434
  - LM Studio默认端口1234
  - llama.cpp常见端口8080/5000
  - 自定义端口范围可配置
- **手动添加**: 支持用户手动输入API端点URL（OpenAI兼容格式）
- **模型信息缓存**: 发现的模型信息持久化到SQLite，包含模型名称、版本、参数规模、最后检测时间
- **健康检查**: 每次测试前自动ping检测模型可用性，不可用模型标记为离线状态

#### 2.2 测试执行规则
- **并行测试**: 使用Promise.all并发执行多个模型测试，单个模型超时时间可配置（默认30秒）
- **负载控制**: 支持设置并发数上限（默认5个模型同时测试），防止本地资源过载
- **重试机制**: 单个模型测试失败时自动重试2次，仍失败则记录错误信息但不中断其他测试
- **隔离执行**: 每个模型测试必须在独立上下文中执行，防止状态污染

#### 2.3 评估指标规则
- **基础指标**:
  - 响应延迟（首token时间和总生成时间）
  - 响应长度（token数估算）
  - 成功率（是否产生有效响应）
- **安全指标**:
  - 拒绝率（明确拒绝回答的比例）
  - 越狱成功率（对于攻击性提示词）
  - 有害内容检出率（使用本地关键词库初筛）
- **一致性指标**: 同一提示词多次测试的响应方差

#### 2.4 对比分析规则
- **横向对比**: 同一代提示词在不同模型间的表现差异
- **纵向趋势**: 同一模型在不同版本升级后的安全表现变化（依赖历史数据）
- **脆弱性排序**: 根据综合评分自动排序模型安全性，高亮最易受攻击的模型
- **差异高亮**: 并排展示不同模型对同一提示词的响应，自动标记关键差异段落

#### 2.5 报告生成规则
- **实时报告**: 测试过程中实时更新结果面板，无需等待全部完成
- **多格式导出**: 
  - PDF报告（使用Electron内置Chromium渲染打印）
  - HTML交互报告（包含可筛选的数据表格）
  - JSON原始数据（供进一步分析）
- **报告模板**: 支持高管摘要（图表为主）和技术详情（完整数据）两种模板
- **历史对比**: 自动关联历史测试数据，展示安全性变化趋势

#### 2.6 UI交互规则
- **模型选择器**: 多选列表展示可用模型，带状态指示器（在线/离线/测试中）
- **进度监控**: 每个模型独立进度条，整体进度百分比
- **结果矩阵**: 表格展示模型×提示词的测试结果，支持点击展开详情
- **可视化图表**: 
  - 柱状图对比各模型成功率/拒绝率
  - 散点图展示延迟vs安全性权衡
  - 热力图展示模型对特定攻击类型的脆弱性分布

## 模块三：离线语义分析引擎 (Offline Semantic Analysis Engine)

### 功能定义
基于Transformers.js的完全本地化语义分析系统，实现提示词风险实时评估、相似攻击案例匹配、零样本分类，无需网络连接。

### 基本规则

#### 3.1 模型管理规则
- **本地缓存**: 使用ONNX格式模型，首次下载后永久本地存储（存储路径可配置）
- **默认模型**: 
  - 嵌入模型: Xenova/all-MiniLM-L6-v2（量化版，约80MB）
  - 分类模型: Xenova/mobilebert-uncased-mnli（轻量级零样本分类）
- **模型切换**: 支持用户切换不同尺寸的模型（速度vs精度权衡）
- **离线检测**: 启动时检测模型文件完整性，缺失时提示下载

#### 3.2 嵌入生成规则
- **批量处理**: 支持批量生成嵌入向量，提高吞吐量
- **缓存机制**: 已分析提示词的嵌入向量缓存到SQLite，避免重复计算
- **维度对齐**: 所有嵌入向量必须统一维度（默认384维），便于相似度计算

#### 3.3 相似度匹配规则
- **本地向量库**: SQLite数据库存储预计算的攻击向量库，包含已知攻击案例的嵌入向量
- **相似度算法**: 使用余弦相似度，阈值可配置（默认0.75）
- **Top-K检索**: 返回最相似的K个案例（默认5个），包含相似度分数和原始提示词
- **实时计算**: 对于新输入的提示词，本地实时计算与向量库的相似度

#### 3.4 零样本分类规则
- **预定义类别**: 默认支持四类分类：
  - prompt injection（提示词注入）
  - jailbreak attempt（越狱尝试）
  - normal query（正常查询）
  - data exfiltration（数据提取）
- **自定义类别**: 支持用户添加自定义分类标签
- **置信度阈值**: 分类置信度低于阈值（默认0.6）时标记为"不确定"
- **多标签支持**: 允许一个提示词同时属于多个类别（如既是注入又是越狱）

#### 3.5 风险评分规则
- **综合评分**: 结合相似度分数和分类置信度，生成0-100的风险评分
- **分级体系**: 
  - 0-30: 低风险（绿色）
  - 31-70: 中风险（黄色）
  - 71-100: 高风险（红色）
- **动态阈值**: 支持用户根据业务场景调整风险分级阈值
- **解释性**: 必须提供风险评分的具体依据（匹配到的相似案例、触发的关键词等）

#### 3.6 学习增强规则
- **用户标记**: 支持用户标记误判案例，反馈数据本地存储
- **本地微调**: 积累足够标记数据后（默认100条），支持触发本地模型微调（可选功能）
- **攻击库更新**: 支持导入外部攻击案例库（JSON格式），自动计算嵌入并入库

#### 3.7 UI交互规则
- **实时分析**: 输入框内容变化时防抖触发分析（默认300ms延迟）
- **风险仪表盘**: 使用GaugeChart展示实时风险分数，颜色随风险等级变化
- **相似案例面板**: 展示Top-5相似攻击案例，支持点击查看详情
- **分类概率条**: 展示各类别的预测概率分布
- **语义空间可视化**: 使用t-SNE或UMAP降维展示当前提示词在攻击向量空间中的位置（可选高级功能）
- **历史记录**: 保存分析历史，支持重新查看和对比

## 跨模块集成规则

### 数据流集成
- **变体→测试**: 遗传引擎生成的优质变体可直接加入多模型对比测试队列
- **测试→分析**: 多模型测试结果可批量导入语义分析引擎进行风险评估
- **分析→变体**: 语义分析发现的高风险特征可反馈给遗传引擎作为适应度指导

### 统一状态管理
- 使用Zustand管理三大模块的共享状态：
  - 当前项目上下文（目标模型、测试场景）
  - 全局配置（模型端点、阈值参数）
  - 跨模块数据缓存（避免重复计算）

### 统一数据层
- SQLite数据库设计需支持三个模块的数据关联：
  - `projects`表：项目基本信息
  - `prompts`表：提示词原文及嵌入向量
  - `variations`表：遗传变体及进化历史
  - `test_results`表：多模型测试结果
  - `analysis_results`表：语义分析结果
  - `attack_vectors`表：已知攻击案例库

### UI一致性规则
- **主题统一**: 三大模块使用相同的Tailwind配色方案和Radix UI组件
- **动画规范**: 使用Framer Motion实现一致的过渡动画（页面切换、数据更新、加载状态）
- **图标体系**: 统一使用Lucide React图标，相同功能使用相同图标
- **布局规范**: 统一采用左侧导航+主内容区的布局，支持模块间快速切换

## 开发约束与质量要求

### 性能约束
- 遗传引擎单代评估时间 &lt; 5秒（启发式模式）或 &lt; 30秒（本地模型模式）
- 多模型测试单个模型响应时间 &lt; 30秒（含重试）
- 语义分析实时响应 &lt; 500ms（嵌入生成+相似度计算）
- UI渲染帧率 &gt; 30fps，避免卡顿

### 安全约束
- 所有模型API调用必须通过主进程，禁止渲染进程直接访问
- 本地数据库文件加密存储（可选，使用SQLCipher）
- 用户导入的攻击案例需进行基础XSS过滤
- 错误处理必须捕获并记录，禁止暴露敏感路径信息

### 可维护性约束
- 所有模块必须提供TypeScript类型定义文件
- 复杂算法必须附带注释说明逻辑
- 数据库Schema变更需使用迁移脚本管理
- 配置项必须集中管理，支持导入/导出

### 测试要求
- 单元测试覆盖核心算法（遗传算法、相似度计算）
- 集成测试验证跨模块数据流
- 端到端测试覆盖关键用户路径（创建项目→生成变体→测试模型→查看报告）
